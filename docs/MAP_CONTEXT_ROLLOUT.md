## Stage gates

**Stage ②:** For every selected map, record source name/version/license and actual geographic extent, independently check each native 1200×760 composition (mainland, islands, exclaves, adjacent land, all insets), compare source vintages and the approved national paths, verify exact path/marker/source SHA preservation, and resolve or explicitly obtain approval for any change in scope. A rejected candidate is an unresolved requested map, **not** a geographic PASS or a completed rollout. Test affected real pages across Desktop / Tablet / Mobile and source credit. The stager `scripts/stage_map_context_rollout.py` does not exclude rejected candidates and its batch artifact is only for read-only QA: every entry now explicitly records `geographicQaStatus: "HOLD"` and `promotionEligible: false`; the existing map-context preflight asserts both values. **This is not a mechanism for geographic approval or production promotion.**

**Stage ③:** Only after Stage ② source-backed disposition and approval for the entire requested roster; regenerate exact current-main roster and SHA; implement reviewed changes on the draft branch, then verify exact affected assets, real pages, markers, accessibility, licenses and unchanged publication. Do not silently omit a country.

**Stage ④:** Only after explicit user final approval: merge/deploy and verify deployed SHA, live page URLs, navigation, `atlasPublished`, robots/noindex and sitemap. Never publish an unapproved Country.
